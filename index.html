Phase 1 — OS Installation, Recovery & Dual Boot (Weeks 1–3)

You are responsible for Windows 10 client installations, understanding Windows RE, and building a dual-boot configuration with Linux. This phase mirrors and extends what Student A is doing — you will eventually swap scenarios to troubleshoot each other's work[cite: 18].

Lab 1-A: BIOS/UEFI Exploration

Your tasks[cite: 18]:

  1. Boot the OptiPlex 3020 #3 into the BIOS/UEFI setup utility[cite: 18].
  2. Record the current boot order, Secure Boot status, and SATA operation mode[cite: 18].
  3. Boot the QCT Pro Tower #1 into its UEFI as well. Note at least three differences in the UEFI interface between the two machines[cite: 18].
  4. On OptiPlex #3, change the boot order to prioritize USB. Save and exit[cite: 18].
  5. Determine whether each machine uses Legacy BIOS or UEFI and document how you identified this[cite: 18].

Think about this[cite: 18]:

  • The QCT tower uses an AMD Ryzen 5 processor. Does CPU architecture affect BIOS configuration?[cite: 18]
  • If Secure Boot is enabled, what happens when you try to boot an unsigned Linux installer?[cite: 18]
  • What is CSM (Compatibility Support Module) and when might you need to enable or disable it?[cite: 18]

Verification checklist[cite: 18]:

  • Both machines' firmware settings documented[cite: 18]
  • Differences between OptiPlex and QCT UEFI noted[cite: 18]
  • Boot order on OptiPlex #3 changed to USB first[cite: 18]

Lab 1-B: Clean Windows 10 Installation — OptiPlex 3020 #3

Install Windows 10 Pro on OptiPlex 3020 #3. This machine will later run a dual-boot configuration, so partition planning is critical. You must leave unallocated space for Linux[cite: 18].

Your tasks[cite: 18]:

  1. Boot from the Windows 10 USB installer. When you reach the partition screen, do not use the full disk. Create a partition of 80 GB for Windows. Leave the remaining space unallocated — do not create a partition there yet[cite: 18].
  2. Complete the Windows installation. Configure a local administrator account[cite: 18].
  3. After the first boot, open Device Manager and resolve any driver issues. Document what was missing and how you fixed it[cite: 18].
  4. Note the Windows version, build number, and edition (Settings > System > About)[cite: 18].
  5. Set a static IP address: 172.16.100.20 / 255.255.255.0. Leave the gateway and DNS blank for now[cite: 18].

⚠️ Partition planning is permanent[cite: 18]:
If you use all the disk space for Windows, you will not be able to create the Linux partition without data loss[cite: 18].
Leave at least 40 GB of unallocated space. Verify in Disk Management before proceeding[cite: 18].

Verification checklist[cite: 18]:

  • Windows 10 Pro installed with 80 GB partition[cite: 18]
  • Unallocated space confirmed in Disk Management[cite: 18]
  • Device Manager shows no errors[cite: 18]
  • Static IP 172.16.100.20 configured[cite: 18]

Lab 1-D: System Restore Points & Windows RE

On both of your Windows machines, you will practice creating restore points and using the Windows Recovery Environment. You will also deliberately break a boot configuration and repair it[cite: 18].

Your tasks — Restore Points[cite: 18]:

  1. On QCT Tower #1, enable System Protection on C: and create a manual restore point. Name it with today's date[cite: 18].
  2. Make two visible changes to the system (install software, change a setting). Then restore back to your restore point and confirm the changes are undone[cite: 18].
  3. Document: what files and settings does System Restore protect? What does it NOT protect?[cite: 18]

Your tasks — Windows RE[cite: 18]:

  1. On OptiPlex #3, access WinRE using Shift + Restart. Document all available tools in the menu[cite: 18].
  2. Open Command Prompt within WinRE. Run and document: sfc /scannow, bootrec /scanos, bootrec /rebuildbcd[cite: 18].
  3. Simulate a broken boot: with instructor supervision, rename the BCD store on OptiPlex #3 so Windows cannot boot. Then repair it using WinRE tools. Document every step[cite: 18].

⚠️ Supervised task[cite: 18]:
Deliberately breaking the boot record should only be done with your instructor present[cite: 18].
Have your USB recovery media ready before you begin[cite: 18].

Verification checklist[cite: 18]:

  • Restore point created and tested on QCT Tower #1[cite: 18]
  • WinRE tools listed[cite: 18]
  • Boot repair completed successfully[cite: 18]
  • All steps documented[cite: 18]

Lab 1-E: Dual-Boot Configuration — Windows 10 & Linux

You will install Ubuntu Linux into the unallocated space on OptiPlex #3 alongside Windows 10. The result will be a working dual-boot system managed by the GRUB bootloader[cite: 18].

Your tasks[cite: 18]:

  1. Boot the OptiPlex #3 from a Ubuntu 22.04 LTS USB installer. Choose the Install Ubuntu option[cite: 18].
  2. When asked about installation type, choose Install Ubuntu alongside Windows Boot Manager (or manual partitioning if that option is not shown). Create a Linux partition in the unallocated space you reserved[cite: 18].
  3. Complete the Ubuntu installation. Set a username and password. Do not encrypt the disk[cite: 18].
  4. After reboot, verify that GRUB appears and both Windows 10 and Ubuntu are selectable entries[cite: 18].
  5. Commands: Boot into Ubuntu. Open a terminal and run the following commands. Document the output of each: ip addr | ping 172.16.100.10 | uname -a | df -h | sudo apt update[cite: 18].
  6. Boot back into Windows 10 and verify it still loads normally and the partition layout is unchanged[cite: 18].

Verification checklist[cite: 18]:

  • Ubuntu installed in unallocated space[cite: 18]
  • GRUB bootloader showing both OS entries[cite: 18]
  • Ubuntu boots and network connectivity confirmed[cite: 18]
  • Windows 10 still boots normally[cite: 18]
  • Linux terminal commands run and documented[cite: 18]

Lab 1-F: Dual-Boot Troubleshooting

You will intentionally break the GRUB bootloader on OptiPlex #3 and then repair it using a live Ubuntu USB. This simulates a common real-world recovery scenario[cite: 18].

Your tasks[cite: 18]:

  1. From within Windows 10 on OptiPlex #3, use diskpart or another method to remove the GRUB entry from the boot sequence. Verify that the machine no longer shows the GRUB menu on next boot[cite: 18].
  2. Boot from the Ubuntu live USB. Open a terminal and repair the GRUB installation. Research the correct sequence of commands using chroot[cite: 18].
  3. Reboot and verify GRUB is restored and both OS entries are present[cite: 18].
  4. Document every command you used in sequence. A colleague should be able to follow your notes to repeat the repair[cite: 18].

Verification checklist[cite: 18]:

  • GRUB successfully removed and confirmed broken[cite: 18]
  • GRUB repaired using live USB[cite: 18]
  • Both OS entries restored in boot menu[cite: 18]
  • Step-by-step repair commands documented[cite: 18]

Lab 2-C: GPO, Drive Mapping & Permission Testing

Student A will configure Group Policy Objects and shared folders. Your job is to verify they apply correctly and to test permissions from different accounts[cite: 18].

Your tasks[cite: 18]:

  1. After logging in as studentB on OptiPlex #3, run gpupdate /force. Wait for it to complete, then run gpresult /r. Document which GPOs are listed as applied[cite: 18].
  2. Verify that the Z: drive is mapped. Open it and confirm you can read files. Attempt to create a file. Document what happens and why[cite: 18].
  3. Log out and log back in as studentA on the same machine. Check if the permissions on shared folders are different. Document any differences[cite: 18].
  4. Use rsop.msc (Resultant Set of Policy) to view the effective policy for the current user. Take notes on what settings are enforced[cite: 18].

Verification checklist[cite: 18]:

  • gpresult /r shows expected GPOs applied[cite: 18]
  • Z: drive visible and access tested[cite: 18]
  • Permission differences between accounts documented[cite: 18]
  • rsop.msc reviewed[cite: 18]
